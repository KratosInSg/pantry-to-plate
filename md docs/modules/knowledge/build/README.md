# `src/knowledge/build/` — the data pipeline

## Purpose

Turns three raw downloads into the curated dataset `data/canonical/` that the application reads. Offline only: **never
imported at run time.**

```
data/FoodData_Central_csv_2026-04-30/  ─┐
data/recipes/  (Food.com)              ─┼─►  run_all.py  ─►  data/canonical/
data/foodkeeper/ (USDA FoodKeeper)     ─┘        ▲
data/canonical/reference/*.csv  (curated) ───────┘
```

Run: `python src/knowledge/build/run_all.py` (≈ 5 minutes). Output description, schemas and caveats:
`data/canonical/README.md` (generated by step 07).

## Steps (order matters)

| Step | File | Reads | Writes |
| --- | --- | --- | --- |
| 01 | [01_usda_nutrition](01_usda_nutrition.md) | USDA CSVs | `nutrition/usda_food_*` |
| 02 | [02_canonical_ingredients](02_canonical_ingredients.md) | Food.com ingredient strings, step 01, `reference/` | `ingredients/*`, `nutrition/ingredient_nutrition_per100g` |
| 03 | [03_recipes](03_recipes.md) | Food.com recipes + interactions, step 02 | `recipes/*`, `interactions/*` |
| 04 | [04_estimate_grams](04_estimate_grams.md) | steps 02–03 | grams + computed nutrition in `recipes/*` |
| 05 | [05_shelf_life](05_shelf_life.md) | FoodKeeper JSON, step 04 | `shelf_life/*` |
| 06 | [06_finalize](06_finalize.md) | everything | pruned tables, `MANIFEST.json`, `_meta/quality_gates.json` |
| 07 | [07_write_readme](07_write_readme.md) | manifest + gates | `data/canonical/README.md` |

Support modules: [config](config.md) (paths, constants), [matcher](matcher.md) (ingredient → USDA/FoodKeeper lexical
matcher), [ingredient_flags](ingredient_flags.md) (food group + allergen/diet rules), [run_all](run_all.md).
The shared name normaliser lives one level up: [`../ingredient_names.md`](../ingredient_names.md).

## Inputs you are meant to edit

`data/canonical/reference/ingredient_synonyms.csv`, `ingredient_usda_overrides.csv`,
`ingredient_foodkeeper_overrides.csv`. Everything else in `data/canonical/` is generated — never hand-edit it.

## Important properties

* **Order-dependent:** step 06 prunes tables that step 03 reads, so re-running a single early step on an already
  finalised dataset is unsafe. Always use `run_all.py`.
* **Deterministic:** no randomness; re-running produces byte-identical Parquet (the manifest hashes prove it).
* **Fails loudly:** step 02 raises if an override names a USDA food that does not exist; step 06 raises on any
  referential-integrity violation.
